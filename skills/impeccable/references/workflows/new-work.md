# Manual Design and Redesign Workflow

Use for a new surface or an explicitly approved visual replacement. `PRODUCT.md` owns product truth. `DESIGN.md` and coherent implemented patterns establish visual authority.

## Establish authority

- **Existing world:** inherit it for local additions and new surfaces unless the user requests replacement.
- **Incomplete world:** preserve confirmed assets and recognizable traits, then extend only what the surface needs.
- **Approved redesign:** preserve product truth, content, function, native affordances, and constraints while replacing the visual world.
- **No visual authority:** create a new world with the user after product truth is known.

## Resolve direction

Choose the mode from the surface, not the product. Ask only for missing facts that change the result. Then derive three materially different, viable directions from the audience's real context, avoiding the category's default template. Each direction must specify:

- visual thesis and cultural source;
- first viewport and reading order;
- color strategy, type character, material, and component language;
- signature interaction and responsive behavior;
- honest risk, required assets, and unsupported claims to avoid.

Recommend one direction with a concrete reason. Obtain approval before replacing an established world. If no answer mechanism exists, choose the strongest evidence-based direction and label assumptions.

## Commit before editing

Write a short direction contract in the working notes or artifact comment: thesis, own world, story, first viewport, and form. If these read as mood words rather than observable decisions, resolve them before code.

Load `craft-floor.md`, then build the smallest complete expression of the approved direction. Use real product facts, label illustrative data, preserve semantics, and keep content visible without optional effects.

## Finish

Inspect desktop and mobile together. Compare the render against the brief and direction contract, fix material gaps in one batch, confirm once, and stop. If the build establishes a durable system, use `document.md` to record what actually shipped.
