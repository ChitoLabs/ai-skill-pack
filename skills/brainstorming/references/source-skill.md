# Brainstorming Workflow

## Purpose

Clarify intent and compare viable designs before implementation.

## Workflow

1. Inspect current repository context and its active workflow policy.
2. Ask one question per turn until goals, constraints, success criteria, and unknowns are clear.
3. Present two or three materially different approaches with tradeoffs and a recommendation.
4. Confirm the selected direction in small sections.
5. Return the validated design to the user or active workflow owner.

## Safety

- Do not write documents, create plans, commit, install, or transition to another phase automatically.
- If a managed workflow owns discovery or design, return control without creating parallel artifacts.
- Use the visual companion only after explicit consent and under its local safety gates.

## Output

Return confirmed requirements, alternatives considered, the selected approach, unresolved questions, and any next action requiring approval.
